# DevKit Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build and verify the responsive DevKit foundation against the supplied reference, then commit and push Phase 1.

**Architecture:** Static HTML, CSS custom properties, and native JavaScript ES modules. A shared tool registry drives dashboard cards, hash routes, workspace shells and command search. Only validated preferences persist; tool input stays in memory.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript; development-only browser testing where available.

**Spec:** docs/reference/DevKit_MASTER_PROMPT.md and docs/reference/DevKit_DESIGN_REFERENCE.png.

## Global Constraints

- No frameworks, bundler requirement, backend, remote fonts, runtime APIs or tracking.
- Default canvas #0B1020, surface #141A2B, elevated #1D2536, accent #8B5CF6; light theme and six accent presets follow the master specification.
- Scope is Phase 1 only. Tool execution belongs to Phases 2–3; shell pages must clearly explain this status.
- Commit and push completed Phase 1 to https://github.com/bojan09/dev-kit.git. Pause before Phase 2.
- Local and remote project folders are empty. The parent directory is a separate Git repository: initialize a dedicated repository inside dev-kit and stage only this project.

## Review Focus

1. Storage denied or malformed: defaults load and the app remains usable.
2. Unknown and direct hash routes: display a useful fallback; back/forward still work.
3. Narrow screens and long labels: no horizontal overflow or hidden navigation.
4. Palette with zero results: arrow/Enter keys remain safe; Escape restores focus.
5. System theme/reduced motion: OS changes and explicit overrides resolve consistently.

**Interfaces:** Registry entries expose id, label, description, icon, keywords and capabilities. Router resolves /, /tools/{id}, /settings and /about from location.hash and renders via a shared main region.

**Interfaces:** loadPreferences(storage) returns validated versioned preferences; updatePreferences(patch) applies and persists allowed settings only. applyPreferences(preferences) updates document attributes and CSS properties.

- [x] Implement light/dark/system, six accents, density, editor preferences, sidebar state, favorites/recent and motion controls; expose privacy and clearing controls.
